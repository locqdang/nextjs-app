# Research: New Menus and HARO Navigation

## Decision: Separate global public navigation from service and account navigation

**Rationale**: A clearer top-level split makes the navbar easier to scan and matches the intended public-versus-app distinction.

## Decision: Use contextual desktop navigation inside HARO

**Rationale**: HARO behaves like a focused sub-area and benefits from direct section links on desktop.

## Decision: Keep `Service` available inside HARO

**Rationale**: Users should not lose access to broader service navigation while they are in HARO.

## Decision: Keep mobile HARO navigation simpler than desktop

**Rationale**: Mirroring the full desktop contextual pattern in the mobile global header would add clutter and reduce clarity.

## Decision: Prefer `Book Meeting` and `Mailbox` labels

**Rationale**: These labels are shorter and clearer than the alternatives noted in the legacy ticket.
